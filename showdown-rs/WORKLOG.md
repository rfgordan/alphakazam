# Work Log — deep-showdown Rust engine

A running log of the engine's development and its verified parity against Pokémon
Showdown (PS). Parity is measured by the differential harness (`crates/verify`): the
engine enumerates *every* outcome branch of a turn, and a turn "matches" if PS's actual
next state is a member of that set (relaxed to the mechanics currently modeled — HP,
status, active slot, boosts, hazards, weather). Representation fidelity (can the engine
losslessly hold a PS state) is tracked separately and has stayed at 100%.

Re-run the metric any time with:

```sh
cd showdown-rs
cargo run --release -p verify -- harness/traces/*.json   # read the AGGREGATE block
VERIFY_DEBUG=1 cargo run -p verify -- harness/traces/trace-seedN.json   # diagnose first mismatch
```

## Content architecture (in progress)

Move *effects* are now data-driven: `engine/src/data.rs` `MoveData` carries `self_boosts`,
`secondary_chance`/`secondary_boosts`/`secondary_status`, `status`, `side_condition`,
`heal`, `self_switch`, and `target_volatile`. `generate.rs` reads these instead of
matching individual move ids — so adding a move is adding a data row, and the data can be
generated from PS. The 2-team slice stays at 100% after this refactor (regression gate).

**Numeric ids + full generated tables (done).** `Species`/`MoveId` are now `u16` newtypes
indexed into `engine/src/gen.rs` — auto-generated by `harness/gen-data.mjs` from PS
(911 species, 954 moves), with `data::move_data`/`base_stats`/`species_types` as O(1)
array lookups and `from_id`/`to_id` as sorted binary search. `Ability`/`Item` stay curated
enums (they encode logic, not just data; unknown ids → `None` = no-op). The 2-team slice
remains 100% on generated data (one codegen bug found+fixed: Salt Cure's volatile is a 100%
`secondary.volatileStatus`, now folded into `target_volatile`). Next: random-battle traces
to surface unmodeled abilities/items.

moves, abilities, items). Traces in `harness/traces-rand/`; verify the same way. Random
battles are the honest measure of *content* coverage — moves are fully data-driven, but
abilities/items are a curated set (unknown → no-op), so this is where the long tail shows.

The 2-team slice stays at **100%** throughout (regression gate). Remaining random-battle
gap is the classic Pokémon long tail, each diagnosable via `VERIFY_DEBUG=1`:
- **hp (~300)**: damage-affecting abilities (Multiscale, Thick Fat, Huge Power, Guts,
  Technician, Adaptability, Tinted Lens, Filter, type-immunity abilities like Flash Fire /
  Water Absorb / Volt Absorb / Sap Sipper), items (Eviolite, Expert Belt, berries,
  Rocky Helmet), variable multi-hit (2–5), fixed-damage moves (Seismic Toss).

Each is a self-contained data row or small hook; the harness names the culprit, so the
grind is mechanical. The representation check is relaxed to the modeled fields (hp, stats,
status, types, boosts, hazards, weather); ability/item/volatiles/tera are excluded.

## Key insight (worth not re-learning)

**Offensive damage modifiers run on the move *category*'s stat event** — `ModifyAtk` for
physical, `ModifySpA` for special — **regardless of `overrideOffensiveStat`**. PS reads
the Defense *value* for Body Press but resets `attackStat` to `atk`/`spa` before
`runEvent('Modify' + stat)` (`sim/battle-actions.ts:1709`). So Body Press (physical,
reads Def) IS boosted by an `atk` best-stat Protosynthesis, by Choice Band, etc. Compare
`proto_stat` to the category's offensive stat, not the stat actually read.

Also: PS's `chainModify([5325, 4096])` is modifier **5325**, not `13/10` (which truncates
to 5324) — a one-unit difference that causes off-by-ones on every Proto-boosted hit.

## Known remaining tail (~8%, diminishing returns)

Each is individually diagnosable via `VERIFY_DEBUG=1`.

- **±1 rounding** — PS's true damage occasionally lands exactly between two of the 16
  enumerated rolls (residual stat/boost-rounding gap vs PS's integer `calculateStat`).
- **active_index (~15 cases)** — fast-U-turn compounds and faint-replacement edges.
- **Compound Garganacl / Leftovers** cases and a few `status`.

Next leverage points if pushing higher: exact integer boost/stat rounding (kill the ±1s),
then the U-turn `active_index` compounds. True 100% ≈ reimplementing all of PS; the
harness provides the continuous metric to drive it.
